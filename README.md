# KOAN Plus

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](./LICENSE)

[English Version Available Here (英語版はこちら)](./README.en.md)

KOAN Plus は、大阪大学のポータルサイト「KOAN」および学習管理システム「CLE」の情報を取得し、見やすいアカデミックダッシュボードとして統合表示する、ローカル完結型の Chrome 拡張機能です。

本拡張機能は、通常の KOAN や CLE のページデザインには影響を与えません。保存済みデータをすぐに表示し、自動ログインが有効な場合は、画面が表示されオンラインの間に古くなった情報だけを自動同期します。手動更新も利用できます。

## 主な機能

- **ダッシュボード表示**: KOANの時間割、8週間先までの休講・教室変更、回答期限の近いアンケート、新着掲示、CLEの課題、CLEの未読メッセージ数、成績などを一元管理。
- **制御された更新（負荷軽減）**: 項目ごとのキャッシュを優先し、別タブの取得結果を共有。連続操作時は保存済みデータを表示し、必要な更新は自動で再試行。
- **CLEとの安全な連携**: ログイン済みのCLEタブを利用し、GETリクエストのみでカレンダーやメッセージのサマリーを取得。
- **掲示板のスナップショット同期**: 自動ログインが有効なら6時間を目安に自動確認。適切なウェイト（遅延）を挟みつつ、ジャンルごとに差分を確認して一覧を取得。詳細な本文は自動取得しません。
- **成績データの同期**: 自動ログインが有効なら6時間を目安に自動取得。成績画面を開く前から準備し、手動更新にも対応。
- **オプションの自動ログインサポート**: IDおよびパスワードを保存した自動ログイン。
- **オプションのMFA自動化**: リスクへの同意を前提とした、TOTP（ワンタイムパスワード）の自動入力。

## データと権限

KOAN Plus は開発者が運営するバックエンド、アクセス解析、広告、クラッシュレポート機能を持ちません。学務情報の取得と認証のため、拡張機能はマニフェストに記載された大阪大学の KOAN、CLE、認証、MFA の各ドメインへ通信します。

ダッシュボードのキャッシュ、成績、CLE課題、掲示メタデータ、設定は、拡張機能オリジンの `localStorage` に保存されます。認証情報は IndexedDB に、更新制御用の一時情報は `chrome.storage.session` に保存されます。セッションクッキーは Chrome が管理し、本拡張機能は Cookie API の権限を要求しません。

自動ログインを有効にした場合、学内個人ID、パスワード、TOTPシークレット、一時解除コードは Web Crypto API の AES-GCM（256-bit）で暗号化されます。ただし、暗号鍵も同じ拡張機能の IndexedDB に保存されるため、これは平文での偶発的な閲覧を防ぐための保護であり、端末、Chromeプロファイル、または拡張機能実行環境が侵害された場合の保護にはなりません。

サイドバーの「お問い合わせ」は Google Forms を開きます。リンクを開くと、拡張機能のバージョンとブラウザの User-Agent がフォームの事前入力値として Google に送信されます。フォームへ入力して送信した内容も Google によって処理されます。

要求する Chrome 権限は `scripting`、`storage`、`tabs`、`downloads`（CLE資料の保存）、`downloads.ui`（一括保存中のダウンロード表示の一時非表示）と、上記4ドメインへのホスト権限です。利用条件は [TERMS.md](./TERMS.md)、詳細なデータ項目、保存期間、削除方法は [PRIVACY.md](./PRIVACY.md)、脆弱性の報告方法は [SECURITY.md](./SECURITY.md) を参照してください。

## 通信・リクエスト方針

KOAN Plus は、軽量なデータ更新と、負荷の高いユーザー操作を意図的に分離しています。

- **自動同期**: 自動ログインが有効な場合、起動・画面切り替え・画面への復帰・再接続と、表示中の30秒ごとのローカル確認で、保存期限を過ぎたデータだけを取得します。30秒ごとに大学サーバーへアクセスするわけではありません。非表示・オフライン中は新しい自動同期を開始しません。
- **手動更新**: 新着掲示・今週の授業変更・CLEの課題一覧とメッセージは直近1分の取得結果を再利用し、それより古ければ確認します。時間割や履修科目などの長いキャッシュは維持します。通信制限中も保存済みデータを使え、必要な更新は画面が表示されオンラインの間に自動で再試行します。
- **更新の重複防止**: Web Locksで画面間の同期を排他制御し、他の画面が保存した結果を取り込んでから更新の必要性を判定します。各取得処理にも通信間隔とリースを設けています。
- **キャッシュの活用 (KOAN)**: 今週の授業変更情報や未読掲示は短い間隔、アンケート一覧と現在の時間割は中程度の間隔、8週間先までの時間割・授業変更情報は6時間、履修科目マッピングは1日1回のキャッシュを使用します。
- **キャッシュの活用 (CLE)**: メッセージサマリーは通常15分、課題一覧は10分、コースマッピングは24時間を目安に更新します。また、個々の課題のステータス詳細（提出済み、採点済み等）の取得は個別リクエストが発生するため、状態ごとに長い更新間隔を設けています。
- **CLE課題の詳細確認**: 期限が近く未完了の課題を優先的にチェックします。通常は期限の30日前以降を対象とし、提出済みの課題は採点を追跡するため対象に残します。採点済みは7日、提出済みは6時間、期限切れは24時間を目安に再確認します。未確認の対象課題が残る間はキャッシュ全体を完了扱いにしません。
- **CLE連絡事項の段階取得**: 現在履修中の科目だけを対象に、表示中または最近利用した科目を優先して1回最大4科目ずつ取得します。科目ごとに2時間のキャッシュを持ち、未取得科目が残る間は次回更新で巡回を続け、取得失敗時は以前のデータを保持します。
- **掲示同期の制限**: 掲示板のスナップショット同期は、6時間のキャッシュを使った自動同期と、掲示画面の **[更新]** から実行されます。初回は一覧を取得し、2回目以降はジャンルごとに既知の掲示だけのページが2ページ続いた時点でページ送りを停止します。ページ上限に到達した場合は完了扱いにせず、取得済みの新着だけを保存します。途中再開時は、現在の形式で取得を完了した新しいジャンルの再取得を省きます。
- **掲示本文の不保持**: 掲示の詳細を開くと未読状態が変わるため、本文の自動事前取得（プリフェッチ）は行いません。
- **表示と再検証の分離**: キャッシュが期限切れでも保存済みデータを先に表示し、更新結果が返ってから差し替えます。同一URLの実行中リクエストは共有し、失敗が続く場合は対象ごとに指数バックオフを適用します。HTTP応答の構造が期待と異なる場合やページングが完了しない場合は、空データで上書きせず「一部未取得」として以前のデータを保持します。
- **成績取得の制限**: 自動同期は6時間を目安とし、成績画面の **[更新]** は直近1分の結果を再利用します。失敗時は保存済みデータを保持し、認証段階の失敗も含めて再試行間隔を延ばします。

掲示同期にはページ数・実行時間・通信間隔の上限があり、本文を自動で開くことはありません。自動ログインを停止すると定期的な自動同期も停止し、更新ボタンからの操作を利用できます。

## ローカルでのインストール方法

本リポジトリにはビルド済みの拡張機能ファイルは含まれていません。ローカルでビルドして Chrome に読み込ませてください。

```sh
npm install
npm run build
```

依存関係はDependabotの週次PRと`package-lock.json`で管理し、更新PRは手動レビュー後に取り込みます。

その後：
1. `chrome://extensions` を開く。
2. 右上の「デベロッパー モード」を有効にする。
3. **[パッケージ化されていない拡張機能を読み込む]** を選択。
4. 生成された `dist/` ディレクトリを選択します。

※ プロジェクトのルートディレクトリをそのまま読み込ませないでください。ルートの `manifest.json` は、誤ったディレクトリを読み込んだ際に開発ガイドを表示するためのダミーです。

## 開発方法と動作環境

開発・テスト・セキュリティ上の注意事項は
[CONTRIBUTING.md](./CONTRIBUTING.md) を参照してください。

### 動作環境

- **対応ブラウザ**: `chrome.storage.session` を利用するため、Google Chrome 102 以上（および同等の Manifest V3 対応 Chromium 系ブラウザ）
- **Node.js**: 20.19 以上、または 22.12 以上 (ローカルビルド時)

### 開発手順

```sh
npm install
npm run dev
```

初回のみUIテスト用のChromiumをインストールし、ユニットテストとUIテストを実行します。

```sh
npx playwright install chromium
npm run test:all
```

個別に実行する場合は、ユニットテストが `npm test`、UIテストが `npm run test:ui` です。

本番用ビルド:
```sh
npm run build
```

配布用ZIPの生成:
```sh
npm run zip
```

`koan-plus.zip` は、生成直前にビルドした `dist/` の内容だけから作成され、
Git では管理されません。

ビルド結果のプレビュー:
```sh
npm run preview
```

`dist/` や `node_modules/`、`*.tsbuildinfo` などの生成ファイルはコミットしないでください。
